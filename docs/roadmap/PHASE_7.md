# Stage 2: 视觉打磨与体验升级

> **状态**: ✅ 已完成 | **时间线**: 2025年Q4 | **依赖**: Phase 6

## 目标

统一视觉设计语言，标准化交互模式，并增强动画/动效系统，以打造连贯、优质且令人惊艳的用户体验。

---

## 概览

本阶段将项目重心从功能开发转移到体验优化。它将解决视觉不一致问题，建立强大的动效设计系统，并打磨用户交互。

| 版本 | 重点 | 关键交付物 |
|------|------|------------|
| **v2.0.0** | **基础建设** | 设计 Token，Tailwind 配置，排版与颜色标准化 |
| **v2.1.0** | **动效系统** | 动画系统，入场动画，微交互 |
| **v2.2.0** | **组件标准** | 标准化按钮、输入框、卡片、模态框 |
| **v2.3.0** | **反馈与打磨** | Toast 系统，加载状态，错误处理，离场动画 |

---

## 路线图细分

### v2.0.0: 设计系统基础
**目标**: 为所有视觉样式建立单一事实来源。

- [ ] **设计 Token**: 创建 `src/styles/tokens.ts` 定义颜色、排版、间距、圆角、阴影。
- [ ] **Tailwind 配置**: 更新 `tailwind.config.js` (或 `index.html` 配置) 将 Token 映射到工具类。
- [ ] **排版审计**: 用基于 Token 的类（H1-H6, Body, Caption）替换临时的字体大小/字重。
- [ ] **颜色审计**: 用语义化颜色 Token（如 `bg-brand-primary`）替换硬编码的 Hex 值（如 `bg-[#E76F51]`）。

### v2.1.0: 动画与动效系统
**目标**: 通过有意义的动效让界面生动起来。

- [ ] **关键帧定义**: 向 Tailwind 配置添加自定义关键帧 (`fade-in-up`, `scale-in`, `border-beam`, `flashlight`)。
- [ ] **入场动画**:
    - [ ] 顶部栏: 淡入 + 下滑。
    - [ ] 相机: 从中心缩放进入。
    - [ ] 画廊: 照片卡片交错上浮淡入。
- [ ] **微交互**:
    - [ ] 按钮: `active:scale-95` 按压效果。
    - [ ] 卡片: 悬停上浮 + 阴影扩散。
    - [ ] 输入框: 聚焦光环 + 轻微上浮。
    - [ ] **手电筒特效**: 画廊卡片上的鼠标跟随渐变。

### v2.2.0: 组件标准化
**目标**: 确保所有 UI 元素在行为和外观上的一致性。

- [ ] **按钮组件**: 创建统一的 `<Button>` 组件及其变体（主要、次要、幽灵、图标）。
- [ ] **输入框组件**: 标准化 `<Input>` 的内边距、圆角和聚焦状态。
- [ ] **模态框系统**: 标准化 `<Modal>` 布局、背景模糊和关闭交互。
- [ ] **卡片组件**: 统一画廊和设置页面的 `<Card>` 容器。

### v2.3.0: 反馈与打磨
**目标**: 清晰且愉悦地传达系统状态。

- [ ] **Toast 通知系统**:
    - [ ] 创建 `ToastContext` 和 `<Toast>` 组件。
    - [ ] 用 Toast（成功、错误、信息）替换所有 `alert()` 调用。
- [ ] **加载状态**:
    - [ ] 用自定义的品牌加载器替换通用加载圈。
    - [ ] 为画廊加载添加骨架屏 (Skeleton)。
- [ ] **离场动画**: 实现 `AnimatePresence`（或类似逻辑）以平滑移除模态框和 Toast。

---

## 成功指标

- **视觉一致性**: 100% 的颜色和字体使用定义的 Token。
- **交互质量**: 所有可交互元素都有悬停 (Hover)、聚焦 (Focus) 和激活 (Active) 状态。
- **动效性能**: 动画运行在 60fps；无布局抖动。
- **代码质量**: 组件文件中零硬编码 Hex 值。
